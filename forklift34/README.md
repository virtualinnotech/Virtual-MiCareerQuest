# Construction forklift challenge

The user-supplied forklift is available in the Construction sector through the
"Construction: pallet delivery" panel. Choose Visit forklift, walk near it and
press T (or click the prompt) to enter. T exits when stopped and an exit is clear.

- W/S or up/down: forward/reverse; A/D or left/right: steering.
- E/Q: raise/lower forks. Space: brake. F: release a grounded pallet.
- Touch buttons provide the same controls. Escape stops and exits.
- Align the lowered forks with the pallet, stop, and raise them to pick up.
- Deliver inside the yellow outline, aligned with it, lower and release.
- Elapsed time and obstruction stops are tracked; Restart challenge resets them.

The vehicle uses rear steering and distance-driven wheel rotation. Travel slows
with a carried pallet or raised forks. Existing navigation geometry provides
conservative vehicle clearance from walls, booths and reserved entrances. A
connected Construction-floor region is selected after booth loading. Booth edits
rebuild clearance. If there is insufficient clear space, the panel reports it.

This is a kinematic learning challenge, not a rigid-body or certified training
simulator. Pallets attach only after alignment and low-speed checks; release
requires floor support. Challenge progress is local to the current page and is
not persisted to the employer database or the existing badge system.

## Integration and deployment

`venue-frame.html` loads `forklift.js` after the main runtime. It uses existing
GLB decoding, rendering, matrix, character and navigation helpers. The optional
character skeleton receives a seated pose; an unloaded character uses a seated
fallback. The embedded venue in v13 is regenerated by `bash splice-venue.sh`.

`forklift.glb` is the animated source asset exported with 1K textures (about
4.4 MB). Original Blender files are kept outside the game repository.

Cloudflare's existing design/venue sync npm commands first copy these two assets
into `booth-shipping/public/forklift34`. Run `npm run sync:forklift` in
`booth-shipping` when invoking Wrangler directly. Publishing the changed venue
still requires the existing `sync:venue-page:remote` command or `npm run deploy`;
deploying static assets alone does not replace the HTML stored in R2.

## Browser regression

Serve the repository root over HTTP, install Playwright in your test environment,
then run `node forklift34/browser-test.cjs`. Default venue URL is
`http://127.0.0.1:8014/venue-frame.html`; override with `VENUE_URL`. Set
`CHROME_PATH` to use an installed Chrome rather than Playwright's browser.

The test mocks read-only manifest/sector responses, never writes to the backend,
and checks desktop/mobile entry, movement, pickup, release and reset. Destination
placement is state-assisted to isolate scoring; this is not a complete automated
drive through a populated live fair. Desktop/mobile screenshots were inspected
separately. Live employer layouts and full-crowd playtesting remain deployment QA.
